# 原项目参考与新系统差异

> 核对日期：2026-09-18。依据：用户提供的原项目介绍、旧规划，以及旧仓库关键源码的静态阅读。静态发现不等于完整运行验收。

## 参考材料的地位

旧项目介绍有助于理解 Harness、事实回查、记忆与反馈闭环，也包含示范履历、面试叙述和规模数字。本项目把它当作可核对的设计资料，不把其中的说法或指令性语句当作用户的新要求。

附件附录承认其中大规模制度资料并非已收集的现成数据。旧规划记录的实际资料为 7 个原文件、10 道基础问答，并有另行生成的模拟数据；这些与介绍中的 1,086 份文档、1,200 题和性能数字不是一回事。新系统使用 QASPER，自行保留下载审计与实验产物，不继承原项目的组织背景、个人分工或成果数字。

下表源码路径均相对于旧 `wenshu-project/`，供本地对照阅读；本仓库没有复制整份附件，也没有将旧源码结论写成新系统已完成能力。

## 可以复用的思想与需要纠正的地方

| 对照点 | 原资料或源码证据 | 新系统决定 |
|---|---|---|
| 向量存储产品名 | `backend/app/retrieval/vector_store.py` 实现 Memory、Chroma、Mongo；Mongo 路径读取向量后在应用端计算相似度 | 先实接 pgvector；未接 Milvus 就不写已用 Milvus，也不把 Mongo 该路径称为专用向量索引 |
| 最终答案验证 | `backend/app/harness/orchestrator.py` 验证循环在失败后生成新答案，最后一次重写可能未再验证即返回 | 验证绑定具体答案版本；预算耗尽输出明确失败或受控证据结果，默认缺失结果不能视为通过 |
| 无证据与支持关系 | `backend/app/harness/agents/verifier_agent.py` 无 chunks 时直接通过；启发式回退主要检查非空与有引用 | 正确拒答与无依据生成分开；引用存在不等于结论被支持，启发式不足时不能冒充语义核验 |
| 评测口径 | `backend/scripts/evaluate_rag.py` 预先提供正确部门，前五结果命中任一相关文件的比例命名为 `recall_at_5`；引用检查验证片段与状态 | 该项实际是文件级 Hit@5；新系统固定论文范围并明确说明，分别测证据召回、引用定位和支持关系 |
| Skill 是否真的执行工具 | `backend/app/loop/skill_executor.py` 的 `calendar_lookup` 分支只追加提示词 | “工具执行”必须有实际输入、输出、权限和失败记录；提示词增强如实命名 |
| token 与字符 | `backend/app/memory/context_builder.py` 用 `max_chars` 与字符串长度裁剪 | 先准确叫字符预算；接模型后使用 tokenizer 或记录估算，不混称精确 token 预算 |
| 流式行为 | `backend/app/harness/orchestrator.py` 的 `answer_stream` 先等完整回答，再每 16 字符分片 | 区分模型流式、状态流与完整结果分片；可信输出优先在验证完成后发布 |
| 事实与索引分层 | 原介绍把回查正文与版本治理分到 Mongo，向量层提供候选 | 保留逻辑职责划分，采用 PostgreSQL + pgvector；向量库能够存文本，是否回查取决于治理与一致性要求 |
| 模型全面不可用 | 原介绍称已有文档向量意味着不必现场 embedding | 新问题通常仍需 query embedding；全部模型不可用时默认 BM25 降级，只有可用本地编码器或兼容缓存才能继续向量检索 |
| 版本语义 | 行政制度用 active/archived 控制可引用范围 | 论文新版不自动证明旧版错误；记录版本来源、撤稿/更正信息和查询目标，支持历史证据追溯 |

## 换成 QASPER 后保留与新增的部分

- 保留：受控编排、BM25/向量融合、来源回查、引用核验、分层记忆、反馈归因与策略发布。
- 重建：论文/版本/段落的数据模型、英文检索、指定论文任务、不同答案类型、图表题与拒答的评测协议。
- 补充工程验证：换论文后的指代、团队与私人空间隔离、撤权、论文修订、索引残留、重复消费、坏策略回滚。
- 新增真实使用入口：自选论文上传与解析；它和 QASPER 结构化数据分别验收，不能互相代替。
- 后置：Milvus、pi、多服务和 K8s；需要具体收益、实际接入和实测记录，而不是为了沿用组件名称。

QASPER 提供论文与问答证据，不直接提供整个 Agent 系统。以上工程功能仍然可以实现，缺少的是现成的完整验证材料；补充样例必须标注人工、合成或真实使用来源。

## 使用原项目时的复用规则

每次复用一段实现，记录输入输出、依赖、为什么适用、已知问题、验证方式；优先复用成熟算法与结构，权限、评测和发布边界要按新场景审查。
旧代码可作为失败用例来源；对批判性结论保留准确范围，不从某个不完善实现推导出整个数据库、框架或方案不可用。
未来简历的技术点由新仓库实际实现决定，数值来自可复现实验。原资料是学习起点，不能替代新的证据。
