# P2B-3 第一轮：DeepSeek 生成、引用核验与真实失败案例

日期：2026-09-22。基础工程检查通过，生成质量验收仍未完成；保持在 P2B，不自动进入 P3。用户学习验收尚未开展。

## 本次交付

工作台在“任务”中可选“检索证据”或“生成并核验回答”。后者调用 `POST /api/v1/answer`，复用所选检索配置，依次执行生成草稿、程序引用检查、模型支持关系核验和发布前事实回查。正式回答只由通过核验的 claims 构成，可展开逐字引用并查看原文上下文。

用户指定 DeepSeek。使用官方 `deepseek-flash`，关闭 thinking、temperature 0、JSON mode、每次最多 2,048 输出 token；一个回答最多两次请求，不自动重试。通过 httpx 直接调用固定官方地址，没有额外引入 Agent 框架：此处只有两个受控模型节点，直接 HTTP 契约便于学习请求、异常和用量；后续需要多供应商时再增加适配器。JSON mode 保证语法不等于满足 schema，Pydantic 仍执行严格业务验证。[接口说明](https://api-docs.deepseek.com/api/create-chat-completion/)

仅在本机 `.env` 配置 `DEEPSEEK_API_KEY`、`DEEPSEEK_MODEL=deepseek-flash`、`RESEARCH_GENERATION_ENABLED=true` 后重启后端。密钥不提交；`/system` 只返回模型名和配置状态，不用它冒充真实服务健康状态。示例配置默认禁用付费生成。显式传入测试文件路径或基础设施配置不会自动读取开发密钥。

## 三层检查分别证明什么

| 检查 | 本次实现 | 不能证明什么 |
|---|---|---|
| 来源/版本 | 限定论文、实际上下文 ID、SHA-256、发布前数据库 revision/版本再次检查 | 不等于身份权限已实现 |
| 引用真实性 | 每个 quote 必须是指定证据的非空连续子串；没有引用或未知 ID 拦截 | 原文中确有这句话，不等于结论受到支持 |
| 语义支持 | 独立请求逐条判断结论，必须完整且无重复编号，全部通过并回答问题 | 同模型会共同误判，不是人工金标或事实真理 |

只发布核验的原草稿并绑定哈希，避免核验之后又生成未经验证的总结。语料变化返回 409；上游异常、截断、无效格式不会变成“证据不足”。不发布被拦截草稿；Trace 保留阶段、摘要哈希、模型、用量和检查结果，尚无持久化运行表。

上下文采用 24,000 Unicode 字符的正文预算，保留完整段落，超限跳过并记录 ID。这是字符预算，非精确 tokenizer 计数；实际 token 来自 API usage。正文与用户问题都是不可信输入；不允许文档指令覆盖模型任务，但提示约束不等于注入防御已被全面证明。

## 实测及失败分析

- 后端 148 项测试通过（含本机 PostgreSQL/S3 集成测试），其中新增 34 项生成链路用例。
- 前端 18 项测试与生产构建通过；覆盖成功回答、失败草稿不展示、切换论文后忽略迟到结果。
- 浏览器真实验证配置状态、任务切换，以及无 BM25 命中时返回证据不足、0 次生成调用；页面展示正常。
- 固定 4 道 dev 题，真实 HTTP 链路共 7 次 DeepSeek 调用；输入 8,827 token、输出 1,096 token。按 2026-09-22 峰时输入无缓存价格估算 $0.003963，非账户账单。[定价依据](https://api-docs.deepseek.com/quick_start/pricing/)
- 原始生成/引用全文仅存在被忽略的 `.local/generation-smoke/`；公开报告保留 ID、哈希、Trace 和用量。没有使用官方 test，没有把答案喂给生成器或核验器。

| 题型 / question_id 前缀 | 系统结果 | 人工阅读发现 |
|---|---|---|
| 自由回答 / 02428a8f | answered，约 8.03 秒（含首次检索模型加载） | 提到先验知识敏感性，和一个参考答案方向一致，但加入多个偏离“定义”问题的结论；不能算完整高质量答案 |
| 是非 / 00c57e45 | answered，约 3.14 秒 | 参考标签是 yes，但返回没有直接限定“仅英文”；把英文示例外推为英文数据集。引用原段未明确证明全部数据语言，核验漏判 |
| 抽取 / 009ce6f2 | evidence_insufficient，约 0.86 秒 | 论文可回答，但本次前五段没有清楚给出所问 baseline；不能简单归咎生成模型。某段命中 gold ID，却可能因 BIBREF 占位符而缺少答案细节 |
| 不可回答 / 003d6f97 | verification_failed，约 2.70 秒 | 生成器尝试回答，核验器拦截；这证明该例拦截发生，不等于整体拒答率达标 |

这四题只是连通与边界观察，不能计算有代表性的总体准确率或 P95。`answered` 的意思是“程序和模型检查都通过”，不能解释为人工已认定正确。失败样例不删、不换题，也不为改善这四题反复调参。

## 如何复现

```bash
RUN_STORAGE_INTEGRATION=1 .venv/bin/python -m pytest -q
npm --prefix frontend test
npm --prefix frontend run build
.venv/bin/python scripts/check_generation.py
```

最后一条仅检查冻结选题，不收费。真实联调需已启动 API、完成向量索引/重排模型并配置 DeepSeek，显式运行 `scripts/check_generation.py --run`；若报告已存在脚本会阻止覆盖及再次付费，须明确归档之后才能重跑。四题配置固定 dense + rerank、top 5。协议见 `P2B-3生成实验协议.md`，选择清单/结果见 `reports/p2b_generation_selection.json`、`reports/p2b_generation_runtime.json`。

## 学习顺序与下一步

依次阅读 `generation.py` 的 Draft/Verification → DeepSeekClient → AnswerService → `test_generation.py` → 前端答复状态。先理解程序可确定校验的部分，再看模型裁判为何不可靠。

下一增量应先针对本次失败完善原子结论与“是否直接回答问题”的评价，冻结新的分层开发评测/人工支持关系标注，比较更强或不同模型裁判的收益和成本。不能直接跳到 Memory 或自进化，也不能把提示词上写了禁止幻觉当作已经解决幻觉。

本阶段未实现：服务整体硬截止时间、分布式限额、鉴权、自动修正、持久化 Trace、多轮记忆、PDF 上传和图表理解。单进程生成门控同时只允许一个在途回答；前端“停止等待”不保证远端停止计费；连接/读超时不是整条工作流的硬超时。
