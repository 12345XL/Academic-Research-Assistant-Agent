# P2B 生成质量与 RRF 参数实验协议 v3

2026-09-22，按用户明确更正冻结：K 指 RRF 平滑常数，不是 top-k。以下配置写入后再运行实验。

## 固定项与变量

- 候选每路 20，融合后最多 20 段重排，最终 5 段；模型/正文/索引保持原版本。**本轮不调候选量或上下文量**。
- RRF 平滑常数 K ∈ {10, 30, 60, 100}；向量权重 α ∈ {0, 0.25, 0.5, 0.75, 1}。权重使用 2(1−α)、2α，使 α=0.5 与历史分数及排名都一致。零权重不引入该路独有候选。
- 每题相同查询、相同两路候选，缓存真实交叉编码器的逐段 logit，供确定性融合网格复用。缓存不能跨问题、正文哈希或模型配置；重排耗时为离线共享计算，不冒充在线延迟。
- 用已冻结 train_tuning 中能计算证据指标的题选参数，先最大化重排后 Recall@5、再 MRR@5；完全相同时优先 α=0.5、K=60，再按网格顺序。与 pure dense、pure BM25、原等权 RRF 同时报结果。
- 参数选择完成并保存之后才处理 train_regression 与 dev_comparison；后两组只报告冻结候选/基线，不据其结果继续调参。dev 已有检索曝光，不是未见测试；官方 test 不访问。
- 保留线上默认 K=60、α=0.5，除非冻结候选在回归/端到端均有充分证据，不根据调参分数自动上线。支持通过 API/页面显式选择实验参数并写入 Trace。

## 生成/核验对照

- 复用 240 题 ID 清单，不重抽。先在 train_tuning 80 题对比 v1 与 v2；两臂使用完全相同 dense+rerank 证据。后在回归与 dev 各 80 题比较同样两臂，以便给出配对变化；没有用结果反复改提示词。
- v1 英文评测臂保留原 JSON 契约和提示原则，仅输出语言改为英文；旧中文四题 smoke 不与本次 F1 混比。
- v2 增加简洁答案与类型契约，简洁答案必须等于首条可核验结论，拒答结构自洽。核验返回每条结论支持/矛盾/证据不足、与问题相关性及逐字支持摘录。程序检查引用必须归属于该条 claim，截断/缺项/重复/伪摘录不能发布。无二次修正循环。
- 主报告：按题型 Answer F1、是非准确率、发布覆盖率、可答题证据不足率、不可答题错误发布率、不同失败状态比例、token/峰时估算费用、端到端耗时。v1 用完整已发布 claims 合并作答案；v2 用已发布的首条简答，显式说明格式差异。Evidence F1 仅用于证据映射完整的样本，另给分母。
- 真实支持率不能用模型自身 verdict 当金标；未完成人工标注时为 null/pending。保留待审阅 JSONL，不写成“人工审核通过”。无输出/故障在端到端 Answer F1 中记 0；只有 evidence_insufficient 可映射官方 unanswerable，verification_failed/model_error 不算正确拒答。未发布率另列。
- 增加可审阅的成对合成核验挑战（支持/数字/否定/条件/全部范围/证据属于别的 claim），冻结后只比较，不自动修改提示以迎合评测。标注来源明确为工程构造，不冒充人类盲审金标。v2 若无效果改善仍保留可选状态，不自动替换线上默认。
- 总付费请求上限 1,000；峰时未缓存费用估算累计上限 \$1（按当前官方价格），逐次调用前预留输入 UTF-8 字节上界与最大输出额度；缺 usage 的失败按预留值记账，不悄悄重试。若达到限制保留部分报告并明确未完成，不追加预算。仅使用用户已配置的 DeepSeek 官方 API。

## 验收与边界

保留数据、模型、配置、提示、代码哈希与各题 ID；正文/问题/参考答案和待审阅全文仅存本机忽略目录。问题与 gold 只由离线评测脚本读，在线模块不能加载评测清单。脚本拒绝覆写完成的付费报告，支持从已完成记录恢复时不得重复消费。单元测试覆盖权重端点/常数/历史零漂移/引用归属/指标分母/费用限制。统计区间按论文聚类 bootstrap，固定种子；80 题一组只支持开发决策，不声称生产 SLA 或最终泛化水平。
