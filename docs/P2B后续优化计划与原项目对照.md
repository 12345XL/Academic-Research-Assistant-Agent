# P2B 后续优化计划与原行政助手源码对照

更新：2026-09-22。用户随后明确 K 指 **RRF 平滑常数**；本轮执行以 `P2B-RRF与生成质量实验协议v3.md` 为准，候选量固定 20、上下文固定 5，下面候选/上下文 K 网格仅保留为此前提议，暂不执行。本文落实用户提出的分层生成评测、核验漏判、K 调优和加权融合。本文件保留早期设计过程；最新已完成的 v3 实验与未通过的质量门见 `P2B-4实验结果与学习路线.md`，下列候选策略不能视为已实现收益。保持既有报告，所有提升要通过同题、同口径对照。

## 1. 顺序与依据

执行顺序：冻结分层评测与错误定义 → 修复核验漏判并比较基线 → 解耦并调优 K → 加权 RRF 消融 → 端到端回归。参数调优与融合候选可以共用离线候选缓存，但只在调参集上选方案。既不承诺融合一定胜过纯向量，也不为追求更高拒答率而让系统全部拒答。

| 步骤 | 为什么现在做 | 交付/退出条件 |
|---|---|---|
| 评测准备（本轮已完成） | 4 题联调不够；中文输出不能直接套英文词重合 F1 | 固定 ID、数据哈希、论文级分组、排除项和复现脚本；0 次模型调用 |
| 生成与 Verifier 修复 | 已观察到范围外推和答非所问漏判 | 原子结论、明确答题、充分/不足/矛盾标签；假通过/误拦截有独立标注与回归；不能只有提示词变长 |
| K 调优 | dense 候选 Hit@20 94.36%，重排 Hit@5 74.09%，151 题在候选命中后被排出前五 | 分开测试候选量与上下文量，记录召回、证据精度、窗口数、token、成本与时延 |
| 加权 RRF | 当前纯向量＋重排胜过等权混合＋重排，需要验证是否词法信号干扰 | 等权、纯向量、加权在同候选预算对照；没有可靠收益则保留现有基线 |
| 端到端确认 | 检索提升不保证回答提升，更多上下文也可能增加无关信息 | 冻结候选后跑回归与 dev 对照，报告各题型/失败状态，不自动进入全量付费实验 |

上表百分比来自 `reports/p2b_reranker_dev.json`，属于已看过的 dev 描述结果；不能用这一结果代替新的调参/回归分离。

## 2. 分层评测设计（已冻结；结果见 P2B-4 报告）

协议：`qasper-stratified-quality-v2`，种子 `qasper-quality-v2-20260922`。清单：`reports/p2b_generation_strata_v2.json`；生成脚本：`scripts/prepare_generation_evaluation.py`；实现：`src/research_agent/evaluation_design.py`。

- 官方 train 按论文 ID 的固定 SHA-256 分组，约 80% 论文进调参池、20% 进回归池；同一论文的多个问题不能跨池。
- 每池分别对抽取、自由回答、是非、不可回答四类，按问题 ID 的固定哈希排序取 20 题：调参 80、回归 80。
- 官方 dev 再固定 80 题作开发期对照，各类 20。dev 检索指标已被反复查看，**不能称为未见测试集**；官方 test 继续不访问。
- 先前 4 道 smoke 题单独作为诊断案例，不加入这 240 题。已知失败可用于开发，但通过它们不能证明泛化。
- 多标注类型不一致、可回答性冲突、是非标签冲突、图表证据、字段缺失均记录 ID 与排除原因；后续另建挑战集。不能因排除难题后分数升高而宣称全体 QASPER 效果提高。
- 生成样本不要求都能映射完整 gold 证据；缺少证据映射的题仍进入相应答案类型分母，单独标记不能计算的检索指标。
- 四类平衡抽样用于诊断，宏平均不等于原数据自然分布下的准确率。小样本必须给分母；后续需要统计区间时按论文聚类重采样，而不是把同篇多个问题当成完全独立观测。
- 当前报告只包含 ID、类别、哈希和覆盖信息，不复制问题、答案或正文；在线服务不导入该模块。

运行 `.venv/bin/python scripts/prepare_generation_evaluation.py` 不联网、不调用模型。重复运行应返回 unchanged；数据或规则改变时拒绝覆盖，需另立版本。240 题是清单规模，不表示已获评测结果，也不意味着每次都要付费跑完。

## 3. 生成与核验要分别评价

### 3.1 答案语言与官方指标

QASPER 官方 Answer F1 基于英文词重合，Evidence F1 评估证据集合；多参考答案有自己的聚合口径，正式实现要对照官方脚本。当前产品给中文回答，不能直接与英文参考计算词重合 F1，也不能把模型自动翻译当作没有误差的中间步骤。[官方评测源码](https://github.com/allenai/qasper-led-baseline/blob/main/scripts/evaluator.py)

下一实现需分离：离线英文简洁答案（用于英文参考 F1）与产品中文逐条解释。答案必须由已核验的结构化内容渲染，不能核验后再生成未经核验的新总结。两种输出分别记录配置；离线英文 F1 不替代中文产品的支持关系抽查。

### 3.2 报告字段与分母

| 指标 | 分母/定义 | 限制 |
|---|---|---|
| Answer F1 | 英文评测配置，按答案类型报告，参考官方归一化与多标注聚合 | 词相似不等于所有事实正确；不能用于当前中文输出 |
| 是非准确率 | 一致的 yes/no 标注题；未答、故障单独记且不能悄悄剔除 | 避免用泛泛描述代替 yes/no/证据不足 |
| 引用可定位率 | 正式回答中的引用，检查 ID、版本与精确摘录 | 全部拒答时分母为 0，应显示 N/A，不是 100% |
| 已发布结论支持率 | 有独立支持标签的已发布原子结论 | 同一个 Verifier 的 passed 不能充当金标；人工和模型审阅分开标注 |
| 错误放行率 / 正确结论误拦截率 | 分别在标注为不支持 / 支持的草稿集合计算 | 单测模拟只证明分支工作，不能当真实模型效果 |
| 发布覆盖率 | 发布回答数 / 所有请求数 | 防止通过大量拒答“提高可信率” |
| 正确证据不足与误拒 | 按 gold 可回答性和本次检索上下文充分性分别报告 | 整篇可答但未检索到不等于生成器一定出错 |
| 故障率、P50/P95、token/费用 | 全部运行，分冷/热启动，故障单列 | 不把 API 超时计为正确拒答；样本不足时不声称 SLA |

核验挑战集建议先建 40 条独立审阅的案例：受支持结论及数字、否定、条件、范围、遗漏等最小改动；覆盖“示例语言不证明全部数据语言”。合成案例和真实模型输出分开统计。若由模型生成/标注，仅能称候选或模型审阅，不能称人工金标。最终人工验收安排在代码和审阅材料可展示之后，不现在开始面试。

### 3.3 修复与归因实验

- 明确原子结论，回答只保留与问题直接相关的信息；是非题显式 yes/no/insufficient，不能用数据集规模绕开问题。
- 核验关注数量、比较对象、条件、否定和“全部/仅/总是”等范围词。要求逐条支持摘录和结构化结论，拒绝缺项、额外项或矛盾项。
- 相同检索与生成配置下，先比较现有 Verifier 与修订 Verifier。再评估更强或不同模型裁判是否值得；模型更大或换供应商不自动消除共同偏差。
- 只在离线诊断中，将人工标注证据直接供给生成器做对照，判断瓶颈在检索还是生成。必须标记 oracle-evidence 实验，不接入在线 RAG，不把成绩与真实检索链路混算。
- BIBREF / TABREF / INLINEFORM 会丢失细节。先统计失败关联，再决定保留相邻段落、章节范围或后续 PDF 解析；不得用标准答案“补全”正文。

## 4. K 不是一个参数

| 名称 | 当前值/行为 | 下一轮候选 |
|---|---|---|
| 每路召回候选量 `K_retrieve` | 通常 20，实际 `max(20, top_k)` | 10、20、40 |
| 送入重排的候选量 `K_rerank` | 通常 20，当前与 top_k 耦合 | 首轮与召回预算同为 N；后续再单独消融 |
| 送入生成的证据量 `K_context` | 默认 5，受 24,000 字符上限约束 | 3、5、8、10 |
| RRF 平滑常数 `c` | 60 | 首轮固定 60；有依据再单独比较 |
| BM25 `k1` | 1.5 | 本轮固定，勿与 top-k 混淆 |

首先需要在服务配置中解耦这些参数，并保持默认配置下旧排名不变；当前代码不能真正测试小于 20 的候选池，单改前端 top_k 不算完成调参。

第一步固定 `K_context=5`，在相同模型下比较 N=10/20/40。第二步冻结候选方案，再测试上下文 3/5/8/10。对每组记录实际保留段落/窗口数和被预算跳过的 ID。重排 50 候选/256 窗口限制不因为调参而暗中提高；超过限制作为失败统计，不能无说明地截断。

调参用 train_tuning，回归集用于冻结方案的检查，不用于反复选最优值；若看了回归结果后继续调参，记录这次查看，后续不能继续把它称为未见验收。旧 745 dev 集保留作历史可比报告，不作为无限次寻优目标。

## 5. 加权融合：先比较加权 RRF

当前是两路等权 RRF；计划使用如下加权形式，其中段落未出现在某一路时，该路贡献为 0：

```text
S(d) = (1 - α) / (c + BM25 名次(d))
     + α       / (c + 向量名次(d))
```

α 表示向量路权重，c=60。先固定网格 α ∈ {0, 0.25, 0.5, 0.75, 1}；0/1 是纯词法/纯向量对照，零权重路线的独有候选不应以零分补入。α=0.5 与当前等权结果应保持排名一致（分数整体缩放不影响排名）。[RRF 原论文](https://plg.uwaterloo.ca/~gvcormac/cormacksigir09-rrf.pdf)介绍的是等权方法；这里的权重网格是本项目待验证的扩展。

不直接把 BM25 原分数与余弦相加：两者尺度不同，且不同问题的分布也不同。归一化后的分数加权可作为后续独立对照，需要说明归一化与缺失候选处理，不能混称为 RRF。

在选定候选预算后比较五组权重，均保持相同重排模型、候选数量、最终 K 和上下文预算；查看新增命中和丢失命中，不能只报平均分。首轮调参主指标为调参集可评检索题的证据 Recall@5，次指标为 MRR@5；数值相同时优先更小候选预算与原有等权配置。策略晋级仍需回归检查和端到端支持率/覆盖率权衡，检索主指标胜出不等于上线。

不先做“模型按问题动态猜权重”：这会引入新的路由变量，妨碍判断固定权重是否有效。若固定权重没有稳定收益，保留纯向量＋重排作为强基线。

## 6. 和原行政助手是否一样

结论：复用了同一类 RAG/Harness 设计思想，但不是相同模型、存储或完整运行实现。以下来自用户提供的本地源码，不是对其线上运行或简历数值的认证。原仓库为并列的 `wenshu-project`，本轮未修改它。

| 项目 | 原行政助手源码 | 科研论文助手当前实现 |
|---|---|---|
| 任务范围 | 学校制度、部门过滤、多 query 接口 | 指定论文，英文正文，当前尚无多轮改写 |
| 词法 | jieba + BM25 | 科研英文标识分词 + BM25 |
| 向量 | 配置默认 relay 的 text-embedding-3-large，另有 local/hash 选项 | 固定本地 BGE-small-en-v1.5，384 维 |
| 融合 | 两路等权 RRF，常数 60 | 两路等权 RRF，常数 60；加权尚未实现 |
| 候选 | 每路默认 20；融合后 `max(top_k*2,10)` 再重排，默认 10 | 默认 20 候选重排，输出 5；三路做同预算消融 |
| 重排 | Relay BGE-reranker-v2-m3；可选本地 CrossEncoder；部分异常回退关键词启发式 | 固定本地 MiniLM 真推理；模型失败明确报错，不把启发式当模型重排 |
| 事实存储 | MongoDB/内存适配；检索后回填 chunk、检查文档 active | PostgreSQL 事务/版本/哈希回查；生成后再检查；S3 保存正文对象 |
| 向量后端 | 构造工厂实现 mongo/chroma/内存；该文件未见 Milvus 分支 | 已实接 pgvector 精确检索 |
| 回答 | 自由文本 `[来源N]`；对候选构造 citations；LLM 失败可拼接原文 | 结构化 claims，每条绑定证据 ID 和精确 quote；异常只展示证据 |
| 核验 | 模型检查；异常回退答案/引用非空检查；最多取 8 段、每段前 500 字符 | 程序检查 ID/quote + 模型逐条支持判断；不可验证则不发布；保留完整入选段落 |
| 工程范围 | 源码还有 Harness、记忆、反馈、pi 等模块和接口，实际启用取决于配置 | 完整 Harness、Memory、反馈 Loop 仍按后续阶段实现；当前不冒称已完成 |

源码定位（原仓库内）：
