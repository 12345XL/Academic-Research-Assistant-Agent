# P4-3：文本 PDF 入库与问答

2026-09-24，从 P4-2 提交 `ce7ce64` 继续。复用现有论文工作台、PostgreSQL、S3、检索器、生成核验、运行记录与反馈；新增单篇文本 PDF 入库，不新增 Agent 框架或评测系统。

## 使用流程

在论文库展开“上传文本 PDF”，选择文件并上传。入库成功后，页面展示页数、文本块数量、解析提示与前三个文本块样例。点击“打开论文并提问”，在模型配置可用时选择回答模式；不会自动发出问题或调用模型。原有纯检索模式增加了“只检索原文，不生成答案”的说明。

PDF 当前支持 BM25 词法检索，禁用向量、混合和重排选项。请使用原文中的英文关键词；现有词法器不支持中文分词，中文问题对英文论文的召回不能保证。解析支持文字抽取，不代表跨语言检索质量通过验收。

引用显示“PDF 第 N 页”，并能查看文本块上下文。页码表示文件中的页序，从 1 开始，不是印刷页码。可下载校验过的原 PDF 和结构化正文；反馈继续绑定这次发布的回答、版本与引用。上传页面样例只辅助核对，入库不需要另一轮人工标注。

## 处理链路与取舍

```text
上传字节 → 限制大小/并发 → 独立进程提取文字与页序
                                ↓
                  原 PDF + 结构化 JSON 写入对象存储并回读校验
                                ↓
                  数据库事务发布论文、版本、段落和文件关联
                                ↓
                  单篇 BM25 → 原有生成、引用检查、语义核验
                                ↓
                  发布前复查 → 回答与页码引用 → 原有反馈
```

解析器为锁定的 pypdf 6.19.0，不使用 OCR。按页面提取文字，合并块内空白，再切成最多 1600 字符的文本块；不会跨页合并，不宣称识别出了真实章节或自然段。标题取文件名，未自动生成摘要。保留原文件字节，避免清洗后的文本替代原始来源。

PDF 内容流的阅读顺序可能不同于视觉顺序，尤其是双栏、表格与公式；抽取文字也可能丢失图像中的信息。[pypdf 官方文字抽取说明](https://pypdf.readthedocs.io/en/6.18.1/user/extract-text.html)解释了这些限制及内存开销。本阶段对所有上传展示版面限制，对少于 40 个非空白字符的页单独提示；这只是启发式检查，不能识别所有乱码或漏字。

原 QASPER 入库是整批发布，原向量索引绑定 QASPER 语料修订号。PDF 复用相同事实表，但不加入该索引快照，也不改变其语料指纹、词频或修订号；单篇 PDF 在请求时建立自己的词法索引。重新导入 QASPER 只更新 QASPER 记录，不隐藏上传论文。数据库汇总显示两类论文的总数。

`pdf-` 加“解析器版本 + 文件字节”的 SHA-256 作为论文 ID。同文件同解析器重复上传复用记录，并校验/修复存储对象，不重复新增论文；更换文件内容产生新 ID。本阶段没有把不同 PDF 自动识别为同一论文的新版，也没有删除或替换入口。

## 可靠性与权限边界

- 非空文件最大 10 MiB、最多 80 页、提取文字最多 50 万字符、单页解压内容流最多 5 MB。无足够文字、加密、损坏、超限 PDF 会被拒绝；文字和扫描页混合文件会提示低文字页，未做 OCR。
- 上传读取最多 60 秒；解析进程最多 30 秒墙钟时间、20 秒 CPU。Linux 使用地址空间限制；macOS 不支持同样的限制，父进程约每 200 ms 检查 RSS，超过 768 MiB 则终止，存在采样间隔，并非瞬时硬上限。进程隔离不是容器安全沙箱。
- 单实例一次处理一个上传；使用原入库锁避免与 QASPER 导入并发。页面关闭不等于后台已取消，处理锁由实际工作线程释放。响应丢失后可以重新上传同一文件确认结果。
- 对象先写入并回读校验，数据库随后在一个事务中发布。失败不会暴露半成品论文；失败对象登记为 orphaned，当前没有自动清理。进程退出后的未完成任务由下一次持锁导入标记失败。
- 上传入口只在 PostgreSQL 的 local_public 模式开放。文件与正文对该工作台使用者共享，不声称私有上传。Bearer 模式禁止上传，但管理员可通过既有论文授权授予上传论文的读取、问答和反馈访问。
- 原 PDF 下载经服务端权限与字节哈希检查，以附件返回，不直接暴露 S3 地址；结构化正文下载继续沿用原接口。保留的 PDF 不是已清除活动内容的安全副本。
- 解析、上传、重试不调用回答模型。后续用户提交问答才可能产生模型费用。PDF 正文仍作为证据数据，不能覆盖服务端指令。

## 学习顺序

沿一次上传看“文件字节 → 页序 → 文本块 → 原文件与派生文件 → 数据库发布 → 检索引用”。重点理解：文件上传成功、数据库发布成功、解析可读、召回答对、生成可靠是不同的验收项。

再沿失败路径看为什么 S3 和 PostgreSQL 不在一个事务中，却仍能保证未发布论文不出现在列表；沿重复上传看内容哈希怎样避免重复记录，以及为什么文件名变化不等于正文变化。

可据实描述为：“接入有界文本 PDF 解析与幂等入库，复用 PostgreSQL/S3 和现有问答核验流程，保留页序与文件指纹，并支持失败回滚和来源核对。”不要写成复杂版面理解、OCR、跨语言语义检索或回答准确率提升。

P4-1/2/3 的本阶段工程增量已完成，用户学习验收和真实回答质量单独保留；不自动进入 P5，不把 P6 反馈策略学习提前并入本次工作。
