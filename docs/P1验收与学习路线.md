日期：2026-09-18。工程验收：通过。用户学习验收：尚未开展；本轮没有进行面试提问。

本阶段的成果是可运行的论文证据检索基线。它为后续可信生成和反馈改进提供数据与比较基准，当前不宣称已经实现完整 Agent。

## 1. 已交付的链路

官方下载包 → 校验来源与 SHA256 → 拆分论文/段落/离线问答 → 构建 BM25 → 限定论文检索 → 返回带定位与文本哈希的原文 → 离线评测。

在线服务只读取 `papers.jsonl` 与 `paragraphs.jsonl`。标准答案、证据标注和不可回答标签保存在 `questions.jsonl`，仅由离线评测读取。
原项目介绍只用于设计对照，没有导入其履历、量级和效果数字；完整附件与个人资料未进入新仓库。

## 3. 真实检索基线

结果文件：[`reports/p1_retrieval_dev.json`](../reports/p1_retrieval_dev.json)。审计文件：[`reports/data_audit.json`](../reports/data_audit.json)。

- 任务：已知目标论文 ID，在该论文的摘要与正文段落内检索。
- 算法：Okapi BM25，`k1=1.5`、`b=0.75`、`top_k=5`；全体 train/dev 正文计算 IDF 与平均段落长度，候选结果限定同一篇论文。
- 分词：英文小写，保留数字及部分连字符/小数/标识符；无停用词过滤、无词干化、无向量、无重排。
- 选择：所有满足预定条件的 dev 问题，按 question_id 排序；未按表现挑题，未看结果后调参。
- 多参考：各指标分别取完整无歧义文本参考中的最佳结果；不直接合并所有标注者的证据集合。
- 覆盖：745 / 1,005 题（74.13%）。另外 75 题可回答性分歧、60 题一致不可回答、125 题没有完整无歧义文本参考。
- 保留：原始问题和异常标注都仍在数据中；不同参考包含图表/文本时，只评完整文本参考，不宣称解读了图表。

| 指标 | 定义 | 本次结果 |
|---|---|---:|
| Hit@5 | 前 5 个结果是否至少命中一个金标证据段落，对问题取平均 | 58.52% |
| Recall@5 | 命中的金标证据段落占该参考全部证据段落比例，再对问题取平均 | 50.64% |
| MRR@5 | 前 5 个结果中首个相关段落名次的倒数，未命中为 0 | 0.3330 |

例：某题需要 2 段证据，前 5 项只命中其中 1 段，则该题 Hit=1、Recall=0.5；两者不能混称。

这份成绩不代表官方 QASPER 问答表现、全库论文发现、跨论文推理、回答正确率或拒答率。模型调用为 0，不报告端到端 Agent 延迟或并发吞吐。
报告记录数据 SHA256、源码摘要哈希、参数、样本 ID、逐题结果与过滤口径；Git 提交保存对应代码。

## 4. 运行与复现

安装和首次下载见 [README](../README.md)。在仓库根目录运行：

```bash
.venv/bin/python scripts/prepare_qasper.py
.venv/bin/python -m pytest -q
PYTHONPATH=src .venv/bin/python -m research_agent.evaluate
.venv/bin/python -m uvicorn research_agent.api:app --app-dir src --host 127.0.0.1 --port 8010
```

服务地址为 `http://127.0.0.1:8010/docs`，终端退出后需重新运行启动命令。初次索引在启动时加载；数据变更后重启。

本机曾出现 editable 安装成功、下次启动却无法导入包的问题。排查确认：`.pth` 文件带 macOS `UF_HIDDEN` 标志，该 Python 的 `site` 模块会跳过隐藏 `.pth`。没有修改系统标志；使用普通安装，以及显式 `PYTHONPATH=src` / `--app-dir src` 源码入口解决。不能将这一现象归因于中文路径或业务检索代码。

## 5. 本阶段的限制

1. 只有英文结构化文本检索，没有 PDF 解析或表格图像理解。
2. 只有原文引用，没有 LLM 生成、语义支持核验和可靠拒答。
3. `trace_id` 与参数仅随本次结果返回，尚未持久化；不能称为已经可回放的 Harness Trace。
4. 没有身份权限、私人上传、数据库、多版本服务、会话 Memory 和反馈策略发布。
5. 没有正式前端；API 文档是临时运行入口。
6. 服务使用单进程内存索引；数据缺失时 `/health` 仍为 HTTP 200，读取 JSON `status` 判断就绪。

## 6. 接下来怎样带着学习

当前不开始面试，先按下面顺序讲解和操作，每次只走一段链路。

| 顺序 | 阅读位置 | 需要理解和观察的内容 |
|---|---|---|
| 1 | `dataset.py` 与 `DATASET.md` | 论文、正文、问题与标准答案的区别；摘要如何变成段落，证据如何定位 |
| 2 | `retrieval.py` | tf、idf、长度归一化、top-k；观察术语改写和数字问题为什么会失败 |
| 3 | `service.py`、`api.py`、`cli.py` | 相同服务如何被 HTTP 与命令行使用；原文、定位和文本哈希承担什么职责 |
| 4 | `evaluate.py` 与报告 | Hit/Recall/MRR 的差别；多参考、排除样本、数据泄漏和任务范围 |
| 5 | 本阶段真实失败案例 | 从低分样本判断下一步需要语义召回、章节过滤还是解析修复，而非直接调大 top-k |
