# P5-1：论文内的最小工作记忆

更新：2026-09-24。工程范围为同一身份、同一论文版本内的有限多轮问答，不代表整个 P5 或真实多轮质量已经验收。

## 1. 本次解决什么问题

此前每次请求只包含当前问题。“What are its limitations?” 没有上一轮上下文，无法知道 its 指什么。本次让用户主动开启“记住本篇对话”，服务器保存有限的已发布问答，供后续追问使用。

继续复用 PostgreSQL、现有工作台、AnswerService、显式状态机、运行预算和授权策略。没有新增数据库、编排框架、模型查询改写服务或评测系统。

## 2. 当前链路

```text
用户开启记忆 → 创建服务器会话（身份 + 论文版本 + 固定到期时间）
提交问题 + 会话 ID + 已读 revision
  → 校验会话归属、论文版本、到期时间、revision
  → 有限规则识别追问；缺少上文或上文截断时提示补充问题
  → 追问使用最近问答作为非证据上下文
  → 当前问题 + 最近一个完整独立问题的前 500 字符，用于本轮检索
  → 现有生成、引用检查、语义核验、发布前检查
  → 发布成功后，以 revision 条件写入本轮工作记忆
```

生成器和核验器收到相同的 conversation_context，系统提示明确要求只能用于理解问题。每轮引用仍必须来自本轮检索的原文，字符串匹配和语义核验照常执行。记忆不能作为可引用段落。

普通独立问题不使用旧上下文。识别规则涵盖“它”“这个方法”“上述”以及 it、its、this method 等有限表达，不是完整语义消歧。上一条回答被截断，或独立问题已移出窗口时，要求用户写明方法名或完整问题。2026-09-24 修复后，不再依据 claim 条数判断语义歧义；多条 claim 也可能讨论同一对象。生成和核验继续收到相同完整上文，模型必须在不确定时弃答。没有新增专门的语义消歧模型，复杂歧义仍是质量边界。

## 3. 存储和生命周期

| 项目 | 当前实现 |
| --- | --- |
| 是否默认保存 | 否；前端勾选后才创建会话并附带会话 ID |
| 保存对象 | 已发布的用户问题、回答文字、run_id、claim 数与截断标记；不存整段引用或离线标签 |
| 单会话上限 | 最近最多 6 轮，问题与回答合计不超过 6000 Unicode 字符；单条回答保留前 3000 字符 |
| 上下文预算 | 记忆与证据一起受既有完整请求序列化字符预算约束；仍非精确 token 或金额预算 |
| 到期 | 创建后固定 24 小时，追问不延长；到期不可读取/追加 |
| 物理清理 | 服务启动、创建和读取会话时清理到期行；不是定时到秒的物理擦除，也不承诺清理数据库备份 |
| 数量 | 单身份最多 50 个未到期会话 |
| 持久化 | PostgreSQL 模式支持服务重启后按 ID 读取；文件模式只存进程内存 |
| 关闭开关 | 暂停使用已有记忆，不等于删除 |
| 清空 | 删除此会话；比较 revision 的追加不会重建已删除会话 |
| 切换论文/身份 | 前端停止旧等待并丢弃当前会话引用，开始新会话；旧服务器会话仍按 TTL 保留 |
| 页面刷新 | 同一标签页的 sessionStorage 仅保存会话 ID、论文 ID、身份标识/模式和记忆开关；刷新后读取服务器最新 revision 和问答，并恢复论文与问答模式。凭证不落盘，授权模式需重新输入同一身份凭证。没有跨设备/会话列表恢复 |

会话身份由服务端鉴权确定，不能由客户端自报。默认 local_public 的身份是共享 local-user，不能称为生产多用户私有记忆。授权模式下读取和执行过程重新检查论文权限。仍可通过有效身份删除自己已失去论文权限的会话。

数据库绑定 current_version_id；文件模式绑定版本标签及段落身份/哈希。换论文、版本变化或到期时不能继续使用旧会话。运行中检测到会话失效，复用 Harness 的停止机制，不继续发布；已发出的模型请求不能撤回或保证不计费。

## 4. 三种记录及其一致性

| 数据 | 用途 | 边界 |
| --- | --- | --- |
| 运行记录 | 执行阶段、预算、会话 ID/revision、使用轮数及上下文摘要哈希 | 仍不保存问题/回答正文；摘要哈希不能恢复内容 |
| 工作记忆 | 理解本篇论文内的后续问题 | 有限、可失效、可删除，不是完整审计档案或事实库 |
| 反馈快照 | 用户明确提交后追溯当时问题、发布回答与引用版本 | 独立保存；清空记忆不删除已提交反馈；未自动附带整段对话 |

发布与记忆追加是两个步骤。回答已发布但追加失败时，返回回答并明确提示“对话保存失败”，不谎称本轮已经记住，也不重发模型请求。响应丢失后可在页面仍持有 ID 时“刷新对话”检查服务器状态。输入 revision 防止两个请求静默覆盖或用旧视图续问；并发和清空竞态通过条件更新检查。

服务器会话本身不接受客户端历史文本。旧回答仍是模型产物，不能凭“曾经核验通过”变成新一轮的事实；语义核验的历史漏判问题没有因增加记忆而消失。

## 6. 学习顺序与下一步

先看 conversation.py：会话为什么要绑定 owner、paper_version、revision、expires_at；再看 api.py 如何在模型调用前后检查这些条件；最后看 generation.py，理解记忆与证据如何在两个模型阶段中保持分离。

重点理解三个不同的“版本”：论文版本决定来源，会话 revision 防止陈旧上下文写入，run_id 标识一次执行。它们不能互相替代。存下历史只是 Memory 的存储部分，读取范围、上下文预算、失效和删除才使它能够受控地参与执行。

P5-1 后续的小修应先由实际追问问题驱动。下一主要增量可以是 P5-2 显式阅读偏好及查看/清除，再按需要推进来源绑定的笔记。P6 的反馈归因和策略发布/回滚尚未实施。本次仅保存学习题目，未进行用户学习验收或面试。

本次总共 2 次真实模型调用。服务器重新读取同一会话，返回 HTTP 200 且保留 1 轮；因此“刷新页面不恢复”的直接缺口是页面没有保存会话定位信息并在加载时读取，而不是 PostgreSQL 未保存问答。

这次发现的质量/可用性问题：多个 claim 不等于多个语义对象；本例各条结论围绕最大熵方法，机械按条数拦截造成追问误阻断。工程测试通过不能证明自然追问可用。下一步应优先补会话恢复并修复这一误拦截，再推进偏好记忆；不据此调整检索参数或重跑全量评测。

## 8. 追问误拦截与刷新恢复修复（2026-09-24）

刷新时先读取服务器的当前身份，再按当前标签页保存的定位信息恢复。正文和凭证不写入浏览器存储；读取会话仍由服务器重新验证身份与论文版本。身份不符、403/404/409 时放弃旧定位；临时故障保留定位并支持手动重试。恢复未完成时不能提交新问题，恢复本身不创建会话或调用模型。切换论文、身份、方向/排序、清空会话时取消待恢复请求，迟到结果不能串入新页面。关闭记忆后刷新仍保持暂停。
