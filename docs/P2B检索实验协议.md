# P2B：混合检索与可信回答

2026-09-22 开始。分三个可验收增量推进：P2B-1 向量与 RRF 检索对照；P2B-2 Reranker 消融；P2B-3 基于证据生成、引用核验与拒答。学习验收单独进行，不能把 P2B-1 完成写成整个 P2B 完成。

## P2B-1 预先固定的选择

- 保持 QASPER train+dev 的原始段落 ID、BM25 分词与参数、单篇检索范围。在线索引只读数据库正文，不读问题或标注。
- 本地 `BAAI/bge-small-en-v1.5`，Hugging Face revision `5c38ec7c405ec4b44b94cc5a9bb96e735b38267a`，384 维、归一化 CLS 向量。固定权重，关闭远程代码和在线隐式下载。
- 问题加官方建议的检索前缀；段落不加前缀。每个正文窗口最多 510 个 tokenizer token，另加两个特殊 token；窗口重叠 64 token。不静默丢弃长段落尾部，段落按最佳窗口余弦相似度排序，最终返回原段落。
- pgvector 精确余弦检索，先限定论文和当前版本；不建 HNSW/IVFFlat。此时单篇只有少量段落，先排除 ANN 误差，后续有扩展需求再比较。
- 对照组：BM25、dense、hybrid。每路候选固定 20，返回 5；用户请求更多结果时每路取 `max(20, top_k)`。RRF 的常数固定 60，两路等权；重复 ID 单路只计一次，同分按 chunk_id 排序。BM25 原始分数与余弦值不能直接相加。
- 默认界面仍选择 BM25。三组结果都保留，不因 dev 结果不理想就隐藏或偷偷修改参数。英文基线不承诺中文跨语言检索质量。

## 评测与验收

复用 `reports/p1_retrieval_dev.json` 冻结的 745 题及相同 evidence-reference 口径，校验问题/正文文件哈希。只比较相同题目的 Hit@5、证据 Recall@5、MRR@5，并逐题确认 BM25 排名没有变化。记录模型身份、索引版本、窗口数量、耗时和差异题数；不把检索相似度写成回答置信度。

三个模式必须经过同一在线服务的事实回查；离线评测可批量生成问题向量以缩短实验耗时，但必须注明这不代表真实在线冷启动延迟。索引缺失、语料换版、模型配置不符时明确报错，不把 BM25 降级结果标成混合检索。建立索引可以断点重试，未完成索引不能提供在线向量结果。

真实数据库集成测试覆盖向量持久化、同篇/同版本隔离、未就绪索引、发布版本变化和篡改后的事实回查；前端验证模式请求与不同分数说明。全量正文索引建成、真实检索与冻结评测完成后，才填写验收结果并提交 GitHub。

## 选择原因与限制

16GB Apple 芯片本机先跑小型英文模型，无每次请求 API 费用，权重可冻结、可离线复现。较大/多语言模型可能更合适中文问题，但增加资源需求，应另建对照实验；付费 Embedding API 要记录成本、数据出境路径、模型版本与重建策略。当前选择用于建立可解释基线，不宣称它在 QASPER 上优于其他模型。

窗口最大值聚合可能偏向长段落；要用后续误差分析检验。RRF 只融合排名，不能证明事实支持；Reranker 和生成/核验属于后续独立增量。取消浏览器请求只会停止前端等待，当前本地同步模型推理可能继续完成。

依据：[BGE 官方模型卡](https://huggingface.co/BAAI/bge-small-en-v1.5)、[pgvector 官方文档](https://github.com/pgvector/pgvector)。
