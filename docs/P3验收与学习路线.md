## 1. 编排采用什么框架

当前使用 **Python 显式状态机与固定工作流**。FastAPI 提供 HTTP 接口，Pydantic 约束输入和模型输出，React 展示结果；没有引入 LangGraph、pi 或自主多 Agent。生成器和核验器是同一模型的两次独立请求，不是两套独立推理系统。

`harness.py` 决定可以进入哪个阶段；`runtime.py` 决定是否还有执行资格；`generation.py` 调用已有检索和模型，并检查证据；`run_store.py` 保存运行元数据。固定流程已经能表达当前任务，新增编排框架暂时不能替代这些约束。

```text
身份认证 → 指定论文授权 → 创建唯一 run_id
  → retrieve：检索与事实回查
  → context：完整段落上下文与预算
  → generate：生成结构化草稿
  → citation_check：引用 ID 与逐字摘录检查
  → verify：模型支持关系与回答目标核验
  → publication_check：复查权限、论文版本、正文哈希
  → publish：保存终态后返回已核验草稿

引用或语义核验失败
  → 默认停止
  → 显式允许修正且预算足够：相同证据重新生成一次
  → 对新草稿重做引用、语义与发布检查
```

无证据、生成弃答、调用异常、取消、超时、越权、存储故障各有独立原因码；未执行的检查不能显示为通过。QASPER 问题与标准答案仍只在离线评测中使用。

## 3. 预算控制到底保证什么

| 配置 | 默认值 | 单位与约束 |
|---|---:|---|
| `RESEARCH_RUN_DEADLINE_SECONDS` | 100 | 创建控制器后的单调时钟时限；包含检索、生成、核验与阶段写入 |
| `RESEARCH_MAX_MODEL_CALLS` | 4 | 服务端最高上限；普通请求进一步收紧为 2，开启修正才允许最多 4 |
| `RESEARCH_MAX_PROMPT_CHARS` | 48000 | 每次序列化完整 messages 的 Unicode 字符数，含 schema；不是 tokenizer 的 token 数 |
| `RESEARCH_MAX_COMPLETION_TOKENS` | 2048 | 每次传给模型供应商的输出 token 上限 |
| `RESEARCH_MAX_REPAIRS` | 1 | 一次引用/语义失败后的草稿修正；需要请求显式 `allow_repair=true` |

原证据上下文上限仍为 24,000 字符。消息预算还计算系统提示、问题、schema、核验材料和修正草稿，不能只检查证据长度。

调用前先预留次数和输出额度，再保存调用元数据，最后才发模型请求。存储失败时不派发新的付费请求。预留不是实际用量：写入失败或终止可能导致请求没有发出；超时或进程退出也可能拿不到供应商 usage，不能把未知记为零或释放后自动补发。当前没有金额账本、用户每日配额或跨进程 token 总预算。

截止时间与取消属于协作式停止。等待端可在后台 I/O 阻塞时结束请求，后台线程退出前继续占用并发名额，迟到结果不再触发核验或发布。Python 不强杀线程，也不能保证已经发送到供应商的请求停止计费。认证、取消查询和终态落库本身会耗时，因此 100 秒不是严格的 HTTP 响应 SLA；请求创建控制器前的受理耗时也不在此计时内。

## 4. 身份与权限边界

未配置 `RESEARCH_ACCESS_POLICY_FILE` 时保持 `local_public`，工作台明确显示“本机公共语料（未启用鉴权）”。这时所有访问者共用 `local-user`，不是多用户隔离。当前本机仍采用该模式。

配置授权时使用服务端文件，其格式如下。占位符需替换成随机高熵 token 的 64 位小写 SHA-256 摘要；不要使用口令或前端自报身份作为授权依据。

```json
{
  "tokens": {
    "<64位小写SHA-256摘要>": {
      "id": "reader-a",
      "allowed_paper_ids": ["1503.00841"]
    }
  }
}
```

文件放在被 Git 忽略的 `.local/access-policy.json`，在本机 `.env` 设置 `RESEARCH_ACCESS_POLICY_FILE` 后重启 API。客户端发送 `Authorization: Bearer <token>`；工作台的“访问凭证”只将 token 保留在当前页面内存，刷新后需重新填写。切换凭证会清空旧身份的论文、答案和运行历史。

空授权列表表示无论文权限，单独的 `["*"]` 表示全部论文。策略路径设置为空、文件损坏或缺失时失败关闭，不悄悄回到公共模式。每次认证与执行检查重读策略；删除 token 或撤销论文授权后，下一个检查点阻止继续执行。列表与统计在数据库分页前按授权范围过滤，受限身份的检索诊断不暴露全库规模。

运行历史同时要求相同身份及当前论文授权，知道 run_id 也不能读取别人的记录。权限不能撤回已经交付客户端的内容；文件策略也不是完整的账号登录、组织 RBAC、凭证到期或企业身份系统。授权变更与数据库提交不是跨系统原子事务，当前保证检查点复查和响应发送前复查，不声称绝对无竞态撤权。

## 5. 持久化、取消与重启

复用 PostgreSQL，新增迁移 `005_answer_runs.sql`。保存 run_id、身份、论文、配置、状态、阶段、尝试、预算、上下文 ID/哈希、调用元数据与检查结果；不保存问题、证据正文、草稿、答案全文或凭证。新历史是执行审计，不是完整会话记录；旧 `.local/` 调用记录继续保留，不自动导入或改写。

| 接口 | 用途 |
|---|---|
| `POST /api/v1/answer` | 原问答接口，增加可选 run_id 和 allow_repair |
| `GET /api/v1/runs?paper_id=...&limit=20` | 当前身份可见的最近运行 |
| `GET /api/v1/runs/{run_id}` | 读取当前身份及论文权限内的快照 |
| `POST /api/v1/runs/{run_id}/cancel` | 请求取消；已完成记录不会被改写 |

run_id 是 32 位小写十六进制字符串，可由浏览器先生成以便取消。相同 ID 再次提交返回冲突，不会自动重放模型调用。取消标记先于最终发布提交时，数据库原子条件拒绝发布；取消发生在已发布之后不能撤销那次结果。前端取消成功提示“请求已接受”，需要读取终态确认，不能仅凭浏览器停止等待声称后端已停止。

PostgreSQL 运行存储在整个服务生命周期持有会话 advisory lock，第二个 worker 启动会被拒绝。重启获得锁后，将上次 `running` 记录转为 `interrupted/server_restarted`，已完成记录保持原样。丢失锁所在连接后失败关闭，不透明重连；旧进程不能继续提交结果。该设计适合本机单实例，不能用多个 API worker 扩容。

重启恢复的是可查询的记录与明确终态，**不会从模型调用中间自动续跑**。进程在发送请求后退出时，远端是否已完成无法从本地记录推断；自动重发可能重复计费。没有引入任务队列、分布式租约或 exactly-once 执行承诺。文件数据模式使用 MemoryRunStore，退出后记录丢失，不能声称持久化。

## 7. 按一条失败路径理解代码

建议先看 `tests/test_runtime.py` 的 `test_api_wait_stops_but_retains_slot_and_ignores_late_response`，再顺着实现读：

1. `api.py` 创建 run 与后台任务；事件循环还能响应取消和查询。
2. `runtime.py` 在执行前后检查时限、取消与身份。生成阻塞时等待端到期，设置停止原因。
3. `harness.py` 保存失败终态；后台没有退出时并发名额保留，第二次问答被拒绝。
4. 旧模型响应稍后返回，执行后的检查拒绝结果；不会再调用核验，更不会覆盖已持久化终态。
5. `run_store.py` 拒绝修改终态；工作台 `RunRecord.tsx` 展示实际原因、预算与未执行阶段。

再看 `test_repair_is_explicit_once_and_reverifies_new_draft`：初稿核验失败 → 相同证据生成新草稿 → 清空旧检查 → 新引用与新语义核验 → 新草稿哈希绑定 → 最终发布检查。这里的“修正”是有上限的工作流支路，没有学习模型权重，也没有证明答得更好。

最后看 `access.py` 的 `authenticate/revalidate` 和 `run_store.py` 的 `save`：前者证明身份和范围来自服务端，后者保证取消先提交时不能发布。身份认证、授权、状态迁移、内容核验、持久提交解决的是不同问题，不能相互替代。

可以用于简历的准确表述：

> 在论文证据问答流程中实现 Python 显式状态机与执行约束，支持服务端论文授权、任务时限、调用前预算预留、一次可选草稿修正及重新核验；复用 PostgreSQL 保存运行元数据，处理取消、迟到响应与重启中断，并通过故障注入和真实存储集成测试验证发布条件。

避免写成完整生产级平台、多 Agent 自主协作、自动恢复付费任务、已解决幻觉或已取得新的准确率提升。
