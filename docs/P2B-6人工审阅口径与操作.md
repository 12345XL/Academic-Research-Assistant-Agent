## 要作出的决定

先回答“哪些输出真的不应发布，哪些只是标准答案没覆盖”，再决定是否值得改核验。沿用 P2B-5 冻结的 24 题，不重新选题；本轮不强制把局部信息一概判错，也不把不确定一概计为正确。

本口径是在模型辅助诊断之后写出的，因此受到既有失败案例启发，不能称预注册的未见评测。上轮模型审阅按原口径保留；本轮新增部分回答与澄清标签，不直接混算两轮支持率。

## 逐项判断规则

| 判断项 | 判定方式 | 容易混淆的边界 |
|---|---|---|
| 证据充分性 | 当前展示的段落是否足以回答所问对象、关系、范围与粒度 | 论文其他地方可能有答案，不代表当前上下文充分 |
| 事实支持 | 每个实质结论能否由其引用证据支持，必要限定是否保留 | 引用逐字存在只是定位检查；相近对象、不同单位不能替代 |
| 回答目标 | 是否给出了问题索取的信息，而不只是谈论同一主题 | 共享任务名称不能代替社交平台名称；介绍方法不一定回答是非 |
| 完整性 | 是否覆盖合理解读下的必要要求，而不是复述整篇论文 | 问方法原理不要求所有实现细节；问两项通常不能悄悄省略一项 |
| 部分回答 | 已回答部分是否有根据，且原草稿明确说明未解决的部分和适用范围 | 审阅者能补出限定，不代表草稿已经表达限定；评价实际文本 |
| 否定结论 | 是否有支持否定的证据，或任务定义在明确范围内足以推出否定 | 没找到发布声明，不等于证明从未发布；无监督不等于非神经 |
| 歧义 | 不同合理解读是否会改变答案或可答性 | 可以记录条件化解释；没有必要把所有开放式问题都转成澄清 |

审阅时采用以下发布行动标签，三项语义判断与行动分别保存：

- **完整回答可发布**：核心事实受支持，目标匹配，覆盖必要要求。
- **有界部分回答可发布**：已答部分受支持，且草稿明确指出欠缺或范围；不把沉默遗漏记为有界。
- **应先澄清**：合理解读分歧会改变答案，草稿未说明采用哪一种解释。
- **当前草稿不应发布**：无依据推断、目标错位或未说明的重要缺项。
- **暂不能裁定**：需要专业知识、更多正文或独立讨论。保留未知，不强迫投票。

生成器已弃答的版本不显示虚构的空白答案评分项；只判断“在当前证据下是否合理弃答”，与核验拦截分开。

## 审阅流程

1. 填写审阅者代号，并声明之前是否看过这些题的报告、答案或判决。看过也可以复核，但结果不能称未曝光独立盲审。工具不验证人的身份，也不能消除记忆影响。
2. **A 阶段**：仅看问题和实际上下文；写出用户需要什么信息，再选择充分、不足或含糊，并记录依据。保存后该阶段锁定。
3. **B 阶段**：查看匿名 A/B 草稿，评价事实支持、目标、完整性和发布行动，或弃答合理性。每个版本记录理由及证据 ID。此时仍不展示数据集标签、版本或原核验结果。保存后锁定。
4. **C 阶段**：展示原标注、候选/上下文位置、版本与原核验判决。它们是对照材料，不是必须服从的裁决。记录是否修改先前判断、最终发布行动及原因；先前 A/B 原记录继续保留。
5. 可逐题进行，不要求一次完成。界面显示已保存和已完成数量；导出 JSON 只保存人工输入、阶段记录、题目 ID 与协议哈希，不导出原论文正文和原始问答。导出不会自动上传，不会修改模型标签或在线知识库。

页面没有预填任何模型审阅结论。已有报告内容不要当作自己的审阅理由。已看过报告的用户可以做知情复核；如需独立人工标签，应让没有看过报告的人使用单独浏览器环境审阅，并如实声明曝光情况。暂不寻找或联系外部审阅者。

## 如何打开与保存

在项目目录执行：

```bash
.venv/bin/python scripts/build_human_trace_review.py
.venv/bin/python -m http.server 8012 --bind 127.0.0.1 --directory .local/trace-audit-v1/review
```

打开 `http://127.0.0.1:8012/`。也可以直接打开生成的 HTML；浏览器对本地文件的存储支持可能不同，页面会提示保存失败。页面没有外部依赖，也不请求模型或业务 API；静态服务仅供本机审阅，不对外发布。服务只暴露生成页面所在目录，不暴露整个仓库或 `.env`。

进度保存在当前浏览器。刷新可恢复，清理浏览器数据会丢失，因此每次结束应导出备份。不要把此页面和完整材料提交 Git。导出的理由可能由审阅者手动粘入论文或个人信息，公开前仍须检查，工具不能保证自由文本天然可公开。

页面将来源材料内嵌在本地 HTML 中，按阶段隐藏，只用于降低先入为主的风险，不是保密或防作弊系统；查看源代码可以提前看到材料。导出记录带有曝光自报和解盲时间，不声称真正双盲。匿名草稿的长短与结构也可能泄露版本。

## 如何使用结果，以及什么时候停止

人工表填写前，不能报告人工支持率或宣称 P2B 质量达标。部分完成必须显示完成题数与两版输出数，不能把空白默认为认可。数据集标签、原模型核验、上轮模型辅助审阅、本轮人工输入分别保存。

审阅结束后，先核对问题要求与争议题，再分开报告：

- 按当前文本可完整发布、有界部分发布、不应发布、应澄清、无法裁定的数量。
- 对实际进入核验的草稿，报告错误放行与错误拦截；弃答不混入核验分母。
- 完整发布与有界部分发布分别统计。是否合并为“可发布”须明示；应澄清与无法裁定不能悄悄丢掉。
- 上下文充分却直接弃答的情况，与论文可答但上下文缺失的情况分别分析。
- A/B 初判与 C 阶段修订分别展示，不用看过 gold 后的改判冒充初判。

若人工认可上轮发现的目标错位/缺项，再冻结固定草稿的核验对照。若多数分歧来自问题含糊或对部分回答的期待，先调整产品回答口径。如果根本缺证据，才转向固定预算的正文结构组织实验。无人工结论时可继续准备材料，不能代填或把另一轮模型判断重新命名成人工评测。
